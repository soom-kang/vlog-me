# k-mood-caption

기준 문서는 [docs/house-style.md](../../../docs/house-style.md)(확정된 작업 방식)와 [docs/caption-style.md](../../../docs/caption-style.md)이고, preset과 제한의 원본은 `renderer/src/production/presets.json`입니다. 문서와 이 Skill이 다르면 문서를 따릅니다. 일반 글쓰기나 원본 분석·음원 선곡만 필요한 요청에는 쓰지 않습니다.

입력은 승인된 run의 후보(`plan.captions`) 또는 timeline v2 자막과 사용자의 수정 요청입니다. 후보에서는 `kind`, `text`, `at`, `duration`을 쓰며 `preset`, `position`, `sub`는 선택입니다. preset을 생략하면 kind의 첫 항목, 위치는 `bottom`을 씁니다. timeline에서는 `preset`, `id`, `from`, `duration`을 프레임 단위로 명시합니다. 이 Skill 자체가 원본 접근·다운로드·렌더 권한을 넓히지는 않습니다.

## 쓰는 순서

1. 화면·전사·사용자 설명으로 장면이 감성인지 예능인지 판정합니다. 관찰과 해석을 나누고 확인할 수 없는 감정·사건을 사실처럼 쓰지 않습니다.
2. 대사 없는 풍경이면 `narration` 또는 `mood` 하나를 고릅니다. 여러 줄의 독백은 `diary`, 한 문장은 `soft-caption`부터 검토합니다. 장소·시간 전환이면 `place`/`chapter`, 실제로 말한 대사만 `dialogue`입니다.
3. 내레이션 읽기 시간에 맞춰 후보의 컷 길이를 조정합니다. 컷을 늘릴 수 없으면 문장을 줄입니다. `\n`으로 나눈 줄이 차례로 나타나며, 다음 장면으로 넘어가기 전에 끝나야 합니다. 최소 2.5초와 권장 시간 계산은 가이드를 따릅니다.
4. 실제로 웃긴 순간이 있을 때만 `deadpan`, `pen-note`, `whisper`, `pen-sfx`, `box-dark` 중 가벼운 예능 자막 하나를 넣습니다. 비율을 채우려고 추가하지 않습니다. 감성 100%도 범위 안입니다.
5. 필요할 때만 `look`과 효과를 정합니다. `look`은 파일 최상위 전역 하나이며 권장값은 `warm 0.5 · grain 0.08 · vignette 0.2 · letterbox 없음`입니다. `light_leak`은 드물게, `dissolve`는 장소·시간 전환에, `drift: true`는 정적인 영상에 씁니다. 사진에는 `drift`를 넣지 않습니다. 레터박스는 영상 전체에 적용됩니다.
6. 사용자가 레퍼런스형(오눅·걍민경) 구어체를 원하면 가이드의 "레퍼런스형 구어체" 절을 따릅니다. 대사 `talk`, 내레이션 `talk-note`, 짧은 한 줄 `talk-mood`, 장소 `place-tiny`(왼쪽 위), 리액션 한 단어 `pop-word`(영상 전체에서 3–4번)를 씁니다. 두 사람 대화가 겹치는 장면은 원음을 끄고 혼자 말하듯 요약 자막만 둡니다.
7. 리뷰 페이지의 감성 비율·내레이션 읽기 경고·자막 겹침을 확인합니다. 검증 오류는 문구·길이·필드를 고쳐 해결하며 제한을 낮추지 않습니다. 승인 범위 안에서 새 리뷰를 보여준 뒤 사용자 선택을 기다립니다. 다음 단계로 자동 진행하지 않습니다.

## 체크리스트

- [ ] kind별 제한 준수: 받아치기 18자, 효과 글자 8자, 내레이션 22자(줄당)
- [ ] 내레이션은 최대 4줄, 다른 kind는 최대 2줄
- [ ] 한 화면에 예능 자막 1개, 감성 자막·내레이션과 겹치지 않음
- [ ] payoff 전에 결말을 자막으로 먼저 말하지 않음
- [ ] `dialogue`는 전사·화면으로 확인한 실제 대사뿐. `의심` 구간은 쓰지 않음
- [ ] 내레이션은 편집자의 독백이며 촬영자의 실제 감정·행동을 단정하지 않음
- [ ] 외모·체형·말투 조롱 없음. 같이 여행한 사람이 보고 웃을 수 있는 수위
- [ ] 위치가 얼굴·하늘선·대사 자막을 가리지 않음(승인된 기대 화면에서 확인)
- [ ] 같은 preset 반복 경고와 내레이션 읽기 경고 확인. 비율과 variation 때문에 문장을 억지로 늘리지 않음
- [ ] 대사 타이밍은 리뷰 카드의 "발화에 맞춤" 결과를 확인. `주의`가 뜨면 직접 고침
- [ ] 검증 결과와 사람이 시청한 결과를 구분해 보고

## 좋은 예와 나쁜 예

| 장면 | 좋은 예 | 나쁜 예 |
| --- | --- | --- |
| 노을 해변 | `narration`/`diary`: `바람이 먼저 와 있었다\n그걸로 충분했다`, sub `a slow day` | `shout`: `감성 폭발!!`로 풍경을 가림 |
| 실제로 길을 잃음 | `variety`/`deadpan`: `(사실 길 잃음)` 하나 | 확인되지 않은 길 잃음을 사실로 만듦 |
| 장소가 바뀜 | `place`/`chapter`: `첫째 날, 제주`, sub `DAY 1` | 장소마다 큰 예능 효과를 반복 |
| 말 없는 창가 | 짧은 `mood` 또는 충분한 시간을 둔 `narration` | 실제로 말하지 않은 문장을 `dialogue`로 씀 |
| 짧은 풍경 컷 | 문장을 줄이거나 허용된 범위에서 컷을 늘림 | 4줄 내레이션을 1초에 몰아넣음 |
| 레퍼런스형 구어체 | `narration`/`talk-note`: `오일은 직접 고를 수 있어요\n저는 코코넛으로!` | `오일은 직접 고를 수 있었다\n코코넛으로 정했다`(문어체 일기투) |
| 대화가 겹친 식사 | 원음 끔 + `talk-note`: `(수다 타임.. 메뉴 얘기만 한참)` | `우리는 좋은 대화를 나눴다`(동행 암시) |

## 사용자가 자막 수정을 요청했을 때

1. `selection.json`의 `note`를 읽고 해당 후보의 `plan.captions`만 고칩니다. 다른 후보는 건드리지 않습니다.
2. `python3 scripts/review.py build --run-id <run>`으로 새 리뷰 버전을 만들고, 고친 카드의 기대 화면을 보여줍니다.
3. 다시 선택을 받아 `review.py select`로 기록합니다.

조립 뒤 `timeline.json`의 자막을 직접 고칠 때도 같은 기준을 따릅니다. timeline에서는 `preset`을 생략할 수 없습니다. 고친 뒤 `python3 scripts/render_prod.py --run-id <run> --check`로 검증합니다.
